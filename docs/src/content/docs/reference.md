Every module's interface, generated by odoc from its `.mli`, where each
function says what it does, what it refuses and what it defaults to.

## The packages

Each library is separate, so a program links only what it uses. A `dune`
file names a library as it is installed (`spindle-http`); OCaml code names
it as a module (`Spindle_http`).

| Package | Libraries | What it is |
|---|---|---|
| `spindle` | `spindle` | The framework; installs `spindle-http` and `spindle-client` with it |
| `spindle-http` | `spindle-http` | HTTP as both ends speak it |
| `spindle-client` | `spindle-client` | Calling another server, which installs and links no framework |
| `spindle-sqlite` | `spindle-sqlite` | A server's SQLite: a pool of one file in WAL mode, a transaction per borrow, sessions |
| `spindle-postgres` | `spindle-postgres` | A server's Postgres: bounded connections, a pool, a transaction per borrow, sessions |
| `spindle-mcp` | `spindle-mcp` | A Model Context Protocol server: the routes an agent calls tools through |
| `spindle-mcp-client` | `spindle-mcp-client`, `spindle-mcp-client.protocol` | Calling another server's tools over MCP, which installs and links no framework, and MCP's messages, which both ends share |
| `spindle-cli` | `spindle-cli` | An application's command line: its API's document, Zod schemas and Melange client |
| [`wiretype`, `ppx_wiretype`](https://hyphatech.github.io/wiretype/) | `wiretype`, `ppx_wiretype` | JSON as descriptions, and the deriver that writes one, released on their own; installed with `spindle` |
| [`rowtype`, `rowtype-sqlite`, `rowtype-postgres`, `rowtype-migrate`](https://hyphatech.github.io/rowtype/) | the same | A statement described once, its SQLite and Postgres backends, and migrations, released on their own; `spindle-sqlite` and `spindle-postgres` each install `rowtype` and their backend, and `rowtype-migrate` is installed beside them (`opam install rowtype-migrate`), which builds the dialect of each backend installed |
| [`postgres-eio`](https://hyphatech.github.io/postgres-eio/) | `postgres-eio` | The Postgres driver, released on its own |

## What it is built on

Each is released and documented on its own site, and links here go to its
reference there.

- [`Wiretype`](https://hyphatech.github.io/wiretype/reference/wiretype/Wiretype/index.html)
  -- JSON as descriptions, and what `[@@deriving wiretype]` writes.
- [`Rowtype`](https://hyphatech.github.io/rowtype/reference/rowtype/Rowtype/index.html)
  -- a statement described once.
- [`Rowtype_sqlite`](https://hyphatech.github.io/rowtype/reference/rowtype-sqlite/Rowtype_sqlite/index.html)
  and
  [`Rowtype_postgres`](https://hyphatech.github.io/rowtype/reference/rowtype-postgres/Rowtype_postgres/index.html)
  -- running one on each database.
- [`Rowtype_migrate`](https://hyphatech.github.io/rowtype/reference/rowtype-migrate/Rowtype_migrate/index.html)
  -- migrations, and each database's way of running them:
  [`Rowtype_migrate_sqlite`](https://hyphatech.github.io/rowtype/reference/rowtype-migrate/Rowtype_migrate_sqlite/index.html)
  and
  [`Rowtype_migrate_postgres`](https://hyphatech.github.io/rowtype/reference/rowtype-migrate/Rowtype_migrate_postgres/index.html).
- [`Postgres_eio`](https://hyphatech.github.io/postgres-eio/reference/postgres-eio/Postgres_eio/index.html)
  -- the driver.
